# Инструкция пользователя

## 1. Что делает инструмент

Загружает MP4-видео и статические JPG/JPEG/PNG в медиатеку выбранных рекламных аккаунтов Meta. Для видео сохраняет `video_id`, для статики — `image_hash`. Поддерживает локальные файлы и бинарные медиафайлы в Google Drive. В одной пачке можно смешивать видео и изображения. Не создаёт объявления, не запускает рекламу и не изменяет бюджеты.

Для работы нужны Python 3.11 или новее, доступ в интернет и действующие доступы к нужным сервисам. Для локальных файлов сторонние Python-библиотеки не нужны.

Пользователь подтвердил live-загрузку статического изображения: оно появилось в Account images кабинета Meta. Это подтверждает путь загрузки статики в данном кабинете, но не проверяет обработку видео, Google Drive или одобрение объявления. Офлайн-тесты используют поддельные ответы API; первый запуск каждого ещё не проверенного сценария делайте на одном небольшом файле. [Отчёт о тестах](TEST_RESULTS.md) можно показать без доступа к кабинетам.

## 2. Подготовка папки

Распакуйте комплект в отдельную папку. Откройте терминал в ней. Все команды ниже выполняются из этой папки.

Проверьте Python:

```powershell
python --version
```

Если команда открывает Microsoft Store или не работает, установите Python с [python.org](https://www.python.org/downloads/) и откройте терминал заново. В некоторых установках Windows вместо `python` используется `py`.

Создайте рабочие копии примеров:

```powershell
Copy-Item config.example.json config.json
New-Item -ItemType Directory -Path creatives -Force
```

На macOS/Linux используйте `cp` вместо `Copy-Item`, `mkdir -p creatives` и при необходимости `python3` вместо `python`.

## 3. Доступ к Meta

Нужны Meta app с доступом к Marketing API, user/system-user access token с правом `ads_management` и доступ этого пользователя к целевому рекламному аккаунту. App token или Page token не являются универсальной заменой. При работе с аккаунтами других компаний могут понадобиться дополнительные настройки доступа приложения и бизнеса.

Порядок подготовки: создайте/выберите приложение в Meta for Developers; настройте Marketing API; предоставьте пользователю или системному пользователю доступ к нужным рекламным аккаунтам; выпустите подходящий токен. Конкретные требования зависят от вашей конфигурации Meta. [Официальная отправная точка](https://github.com/facebook/facebook-python-business-sdk#pre-requisites).

Для личного запуска можно записать токен в локальный `config.json` в поле `token` нужного профиля. `config.json` исключён из Git через `.gitignore` и не включается в release-архив. Это удобнее для повторных запусков, но токен хранится на диске открытым текстом: не пересылайте этот файл, не добавляйте его через `git add -f` и не кладите копию в публичный каталог. Meta access token не становится «одноразовым» после первого запроса; он используется до истечения срока действия или отзыва. Если токен уже был показан на скриншоте или в терминале, перевыпустите его.

В скопированном примере заполните пустое поле `"token": ""` в нужном профиле. Если у вас старый `config.json` с `token_env`, удалите эту строку и добавьте `"token": "ВАШ_ТОКЕН"`. У профиля должен быть ровно один способ получения токена: `token` или `token_env`. Значение токена не печатается в ошибках, `plan` и отчётах. Не вставляйте токен в `.py`, `jobs.json`, аргументы командной строки или переписку.

Если хранить токен в файле нежелательно, замените `token` на `token_env`: это имя переменной (например, `META_TOKEN_PRODUCT_A`), а не сам токен. Для PowerShell ниже показан вариант без записи значения в историю команд.

В PowerShell, с вводом без отображения токена и без записи его значения в историю команд:

```powershell
$uaToken = Read-Host 'Meta access token для product_a' -AsSecureString
$env:META_TOKEN_PRODUCT_A = [System.Net.NetworkCredential]::new('', $uaToken).Password
$uaToken = $null
```

Для второго профиля повторите с `META_TOKEN_PRODUCT_B`. Переменные действуют в текущем терминале и дочерних процессах; после его закрытия ввод потребуется повторить. Для планировщика задавайте секреты в его защищённой конфигурации запуска.

На bash:

```bash
read -rs -p 'Meta access token: ' META_TOKEN_PRODUCT_A
export META_TOKEN_PRODUCT_A
```

Файлы `.env` автоматически не загружаются. Не передавайте токен аргументом командной строки.

## 4. Настройка продуктов и аккаунтов

Откройте `config.json`. Замените `REPLACE_WITH_ACCOUNT_ID` своим ID. Допустимы цифры или формат `act_` с цифрами. Удалите ненужный второй профиль: даже неиспользуемые профили должны иметь корректный `account_id`.

```json
{
  "api_version": "v26.0",
  "state_dir": "state",
  "max_file_bytes": 2147483648,
  "drive_credentials_env": "GOOGLE_APPLICATION_CREDENTIALS",
  "profiles": {
    "product_a": {
      "product": "product_a",
      "account_id": "REPLACE_WITH_ACCOUNT_ID",
      "token": "ВАШ_ТОКЕН"
    }
  }
}
```

`product` — ваша организационная метка. Она не выбирает app ID в Meta и не изменяет настройки атрибуции. `profile` однозначно определяет аккаунт и credentials. Один продукт может иметь несколько профилей. Один токен может обслуживать несколько профилей, если ему действительно открыт доступ ко всем этим аккаунтам.

`api_version` задана явно. В примере используется `v26.0`, указанная в [конфигурации официального Meta SDK](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/apiconfig.py). Это не подтверждение live-совместимости: при развёртывании проверьте поддержку версии вашим приложением и выполните `check`. Версия не обновляется автоматически.

Если приложение требует App Secret Proof, добавьте в соответствующий профиль:

```json
"app_secret_env": "META_APP_SECRET_PRODUCT_A"
```

Задайте секрет приложения одноимённой переменной окружения так же, как токен. Инструмент рассчитает HMAC proof для API-запросов. Используйте секрет того приложения, которое выпустило токен. Сам секрет в Meta-запросы не отправляется.

`state_dir` считается относительно config-файла. Сохраняйте один постоянный каталог состояния для всех запусков, работающих с одной медиатекой. `max_file_bytes` — локальный предел размера, не утверждение о лимите Meta для видео или изображений. Файлы обрабатываются последовательно; на диске нужна свободная ёмкость для рабочей копии текущего файла.

## 5. Массовая загрузка из папки и отдельные задания

Обычный сценарий: положите все файлы `.mp4`, `.jpg`, `.jpeg` и `.png` в `creatives/`. Вложенные папки тоже обрабатываются. Файлы сортируются по относительному пути, название креатива берётся из имени файла без расширения. Неподдерживаемые файлы пропускаются; их количество показано в плане и выводе команд. Пустая папка или папка без поддерживаемых файлов вызывает ошибку. Медиафайл с поддерживаемым расширением, но неверным содержимым отклоняется при проверке. При необходимости разбейте файлы по подпапкам, например по дате или пакету.

```powershell
python meta_upload.py --config config.json plan --directory creatives --profile product_a
python meta_upload.py --config config.json check --directory creatives --profile product_a
python meta_upload.py --config config.json upload --directory creatives --profile product_a
```

Для другого аккаунта укажите его профиль и соответствующую папку. Команда обрабатывает файлы последовательно и сохраняет результат каждого; повторный запуск проверяет SHA-256 в реестре выбранного аккаунта и не загружает уже известные байты второй раз. Автоматический поиск убирает ручное перечисление файлов, но саму передачу в Meta быстрее не делает. Скорость зависит прежде всего от размеров файлов, сети, обработки Meta и числа API-запросов. Не запускайте несколько копий одновременно с одним `state_dir`.

`jobs.json` нужен, когда в одной пачке смешаны профили, файлу требуется название, отличное от имени файла, или источник находится в Google Drive. Для него скопируйте пример:

```powershell
Copy-Item jobs.local.example.json jobs.json
```

Настройте `jobs.json`:

```json
[
  {
    "job_id": "creative_001",
    "profile": "product_a",
    "title": "creative_001",
    "source": {"type": "local", "path": "creatives/video.mp4"}
  }
]
```

- `job_id` должен быть уникален внутри пачки; допустимы латинские буквы, цифры, `_`, `-`.
- `profile` должен существовать в config.
- `title` — название в отчёте, до 200 символов. Для видео оно передаётся как title. Для изображения из него формируется безопасное ASCII-имя файла при отправке в Meta; нелатинские символы заменяются `_`. Название не определяет идентичность файла.
- Относительный `path` считается от местоположения `jobs.json`. Абсолютный путь тоже допустим.
- Для отправки одного файла в два аккаунта добавьте два задания с разными `job_id` и профилями.

Для статики структура задания такая же:

```json
{
  "job_id": "image_001",
  "profile": "product_a",
  "title": "banner_001",
  "source": {"type": "local", "path": "creatives/banner.png"}
}
```

Для JPEG укажите путь с `.jpg` или `.jpeg`. Отдельный переключатель типа не нужен: инструмент определяет тип по содержимому и сверяет его с расширением или MIME из Drive. Готовый пример смешанной пачки находится в [jobs.mixed.example.json](jobs.mixed.example.json).

Локально проверяется размер, MP4-заголовок, JPEG-маркеры начала/конца и структура/CRC PNG. Анимированный PNG (APNG), GIF, WebP и другие форматы не поддерживаются. Полное декодирование пикселей/видео, проверка кодека, длительности, цветового профиля и пригодности для конкретных placements не выполняются. Успешная загрузка изображения не означает одобрение будущего объявления.

## 6. План → проверка → загрузка

Офлайн-план: без токенов, сетевых запросов и загрузки. Для локальных файлов также вычисляется SHA-256; для Drive проверяется только структура задания.

Три команды для массовой загрузки из папки приведены выше. Если используете `jobs.json`, добавьте `--jobs jobs.json` вместо пары `--directory creatives --profile product_a`:

```powershell
python meta_upload.py --config config.json plan --jobs jobs.json
```

Проверка доступа и источников без записи в рекламный аккаунт:

```powershell
python meta_upload.py --config config.json check --jobs jobs.json
```

`check` проверяет доступность активного аккаунта, чтение нужных медиатек (`advideos`/`adimages`) и исходников. Успешная проверка чтения не гарантирует право записи или принятие/кодирование файла. Для Drive содержимое скачивается и проверяется во время upload; check проверяет метаданные.

Загрузка:

```powershell
python meta_upload.py --config config.json upload --jobs jobs.json --wait-seconds 30
```

`upload` — команда, которая действительно загружает файлы в Meta. Она сама повторяет предварительную проверку всей пачки. Если preflight не прошёл, загрузки не начинаются. Видео идут через `advideos`, изображения — через `adimages`. `--wait-seconds` ограничивает период опроса обработки каждого видео; отдельный HTTP-запрос может занять больше этого времени. `0` означает одну проверку статуса без последующего ожидания. Для изображения выполняется проверка полученного image_hash в выбранном аккаунте; отдельный video encoding poll не используется.

Прогресс и результаты записываются после каждого задания в `state/runs/<run_id>/results.json`. Путь итогового файла печатается в терминале. Пустая пачка также получает отдельный отчёт. История реестра хранится в `state/archive.sqlite3`.

## 7. Результаты и коды завершения

| Статус | Значение и действие |
|---|---|
| `READY` | Видео готово либо загруженное изображение найдено в выбранном аккаунте со статусом ACTIVE |
| `SKIPPED` | Содержимое уже известно этому аккаунту; существующий объект повторно проверен |
| `UPLOADED` | Промежуточная запись реестра: image_hash сохранён, проверка доступности изображения ещё не завершилась |
| `PROCESSING` | Видео принято, но обработка ещё не завершена; выполните reconcile позже |
| `PROCESSING_FAILED` | Meta сообщает об ошибке обработки; проверьте исходник и объект |
| `UNKNOWN_OUTCOME` | Запрос мог изменить удалённое состояние; автоматическая повторная загрузка заблокирована |
| `NEEDS_RECONCILIATION` | Есть запись реестра, но текущий статус не удалось проверить |
| `FAILED` | Задание не выполнено; смотрите безопасное описание ошибки |
| `INTERRUPTED` | Локальный сбой или прерывание; проверьте реестр перед следующим запуском |
| `PENDING` | До задания не дошёл прерванный запуск |

Коды процесса: `0` — все задания READY/SKIPPED либо успешная проверка; `1` — есть нерешённые задания, включая PROCESSING; `2` — ошибка конфигурации/preflight или критическая ошибка выполнения; `130` — прерывание пользователем.

Итог содержит `processed`, `ready`, `skipped`, `unresolved`. Ошибки тоже считаются обработанными заданиями. В каждой обработанной записи указаны `media_type`, `mime_type`, локальный `sha256` и удалённый идентификатор: `video_id` или `image_hash`. SHA-256 исходного файла и Meta image_hash — разные значения, не подставляйте одно вместо другого. Чтение registry:

```powershell
python meta_upload.py --config config.json status
```

Команда может вывести ID аккаунтов и названия креативов — это рабочие данные. Отчёт запуска является снимком: последующая сверка изменяет реестр, но не переписывает старый отчёт.

## 8. Повторный запуск и восстановление

Обычный повтор той же пачки использует SHA-256 и аккаунт. Переименование файла не приводит к повторной загрузке. Изменение байтов файла считается новым содержимым. Проверка использует локальный реестр: файлы, загруженные ранее вручную или другим инструментом, автоматически по содержимому не распознаются. Прежние записи видео без поля media_type продолжают работать: они интерпретируются как video.

Для сверки сохранённого video ID или image_hash возьмите локальный `sha256` из отчёта:

```powershell
python meta_upload.py --config config.json reconcile --profile product_a --sha256 REPLACE_WITH_SHA256
```

Если известное видео готово или изображение найдено в аккаунте со статусом ACTIVE, реестр перейдёт в READY. Если незавершённая видеозагрузка всё ещё «processing», неопределённость сохраняется: инструмент не делает вывод, что этап finish состоялся.

Если удалённый идентификатор не успел сохраниться, найдите объект в медиатеке и самостоятельно сопоставьте его с исходником. Для привязки существующего READY-видео:

```powershell
python meta_upload.py --config config.json adopt --profile product_a --sha256 REPLACE_WITH_SHA256 --video-id REPLACE_WITH_VIDEO_ID --confirm-content-match
```

Для существующего изображения вместо `--video-id` используйте `--image-hash`:

```powershell
python meta_upload.py --config config.json adopt --profile product_a --sha256 REPLACE_WITH_LOCAL_SHA256 --image-hash REPLACE_WITH_META_IMAGE_HASH --confirm-content-match
```

Эти два аргумента взаимоисключающие. `adopt` проверяет принадлежность аккаунту и готовность/ACTIVE-статус объекта. Совпадение содержимого подтверждаете вы: API-проверки локального SHA-256 удалённого медиа здесь нет. Команда подходит и для заранее существующего объекта; SHA-256 локального файла можно взять из `plan`.

Если ранее известный объект стал недоступен, reconcile пометит запись как NEEDS_RECONCILIATION. Сначала проверьте токен и права: ошибка чтения не доказывает удаление. Если объект действительно удалён и это проверено, используйте reset; при временной ошибке доступа достаточно повторить сверку.

Только когда вы установили, что незавершённая/ошибочная операция не оставила удалённого объекта, можно снять блокировку:

```powershell
python meta_upload.py --config config.json reset --profile product_a --sha256 REPLACE_WITH_SHA256 --confirm-no-remote-object
```

После этого повторите upload. `reset` ничего не удаляет в Meta и сам не проверяет отсутствие объекта; неверное подтверждение может создать дубль. Если объект существует, используйте сверку/adopt либо разберите его вручную. Удалять SQLite-файл для обхода блокировки не следует: вы потеряете защиту от повторных загрузок.

Инструмент сохраняет upload session и offsets для диагностики, но не возобновляет автоматически прерванный transfer. Неопределённые POST не повторяются. GET повторяются до трёх попыток при временных транспортных ошибках, HTTP 429 и 5xx.

## 9. Google Drive — дополнительный источник

Этот шаг не нужен для локальных файлов.

Создайте виртуальное окружение и установите зависимость:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-drive.txt
```

Далее запускайте uploader через `.venv\Scripts\python.exe`. На macOS/Linux используйте `.venv/bin/python`.

В Google Cloud включите Drive API, создайте service account и получите его JSON credentials согласно политике вашей организации. Дайте email сервисного аккаунта право чтения исходного файла/папки. Не требуется выдавать доступ ко всему домену. Для Shared Drive должны быть предоставлены соответствующие права. [Service-account authentication](https://developers.google.com/identity/protocols/oauth2/service-account).

Храните JSON-ключ вне папки проекта и укажите его путь:

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS = 'C:\secure\service-account.json'
```

Это условный путь — замените его своим. Для macOS/Linux используйте `export GOOGLE_APPLICATION_CREDENTIALS='/your/private/path/key.json'`.

Пример задания:

```json
{
  "job_id": "creative_002",
  "profile": "product_a",
  "title": "creative_002",
  "source": {"type": "drive", "file_id": "REPLACE_WITH_DRIVE_FILE_ID"}
}
```

Нужен ID самого файла, не URL папки. В одной пачке можно смешивать local и drive. Поддерживаются бинарные MP4/JPEG/PNG с MIME `video/mp4`, `image/jpeg` или `image/png`; Google Docs, shortcuts и Google Vids не обрабатываются. Для статики используется точно такое же Drive-задание — отдельный тип в manifest не требуется.

Загрузчик проверяет доступность скачивания, размер, MIME, checksum и версию до/после скачивания. При изменении файла либо неполной загрузке задание отклоняется. Этот механизм использует [Drive files.get / alt=media](https://developers.google.com/workspace/drive/api/guides/manage-downloads).

## 10. Хранение и перенос

Не публикуйте `config.json`, реальные manifests, `state/`, `.env`, ключи сервисных аккаунтов и рабочие медиафайлы. `.gitignore` исключает стандартные рабочие файлы, но не может обнаружить секреты под любым произвольным именем.

Для переноса остановите uploader и перенесите весь каталог `state` вместе с конфигурацией безопасным способом. Не копируйте SQLite во время работы процесса. Не запускайте две независимые копии state для одного аккаунта: их реестры не знают друг о друге. Блокировка рассчитана на локальную файловую систему одного компьютера; сетевой каталог и несколько хостов не поддерживаются.

Штатные временные копии удаляются после задания. После аварийного завершения процесса могут остаться файлы в `state/staging/`: удаляйте их только когда никакой uploader не работает. Каталог `state/runs/` хранит отчёты без автоматической очистки; настройте срок хранения по своим требованиям.

Токены отправляются в Authorization header и не добавляются в URL загрузчика. Не включайте стороннее HTTP-debug логирование с секретами. По умолчанию ошибки не содержат сырые ответы API; HTTP-код показывает тип сбоя, но для диагностики конкретных разрешений может потребоваться проверка настроек Meta/Google.

## 11. Проверка установки

```powershell
python -m unittest discover -s tests -v
python run_tests.py --report TEST_RESULTS.md
python meta_upload.py --help
```

`run_tests.py` блокирует сетевые соединения, запускает тесты и автоматически создаёт Markdown-отчёт с итогом каждого теста и SHA-256 исходников. Этот файл подходит для демонстрации логики инструмента без реальных кабинетов. Уже сформированный отчёт — [TEST_RESULTS.md](TEST_RESULTS.md).

Тесты не используют ваши токены и не обращаются к рекламным аккаунтам. Отдельная пользовательская live-проверка подтвердила появление статики в медиатеке Meta; тесты и этот пример не доказывают фактическое кодирование видео или пригодность файла для конкретного объявления.
